# Grape Bunch Detection — Dataset Preprocessing Pipeline

## Overview

This repository contains the **dataset preprocessing pipeline** for a PhD research project on **grape bunch detection**. The pipeline prepares the [GrapesNet](https://data.mendeley.com/datasets/mhzmzd5cwx/1) dataset (and, later, other compatible vineyard/fruit-detection datasets) for training a YOLO-based object detection model (YOLOv11 or YOLOv12 — final model version not yet decided).

This is **preprocessing only**. Model training, the custom detection architecture being developed for the PhD, and live-video/tracking deployment are separate, later stages of the project and are out of scope for this repository.

> **Training safety:** GrapesNet images in this workspace currently have no verified bounding-box annotations. The pipeline intentionally refuses to create a YOLO training dataset from guessed boxes. Annotate/review the RGB images first, then run preprocessing.

## Project Context

- **Task:** Single-class object detection — detecting grape bunches (`grape_bunch`) in vineyard images.
- **Dataset:** GrapesNet — 11,000+ RGB/RGB-D images of white grape clusters captured in real Indian vineyards, split into 5 sub-datasets (`Dataset-1`, `Dataset-1b`, `Dataset-2`, `Dataset-3`, `Dataset-4`), each with different backgrounds, lighting, and single-vs-multi-cluster framing.
- **Why this matters for the PhD:** Existing published work on grape bunch detection (YOLOv3–v8 based) is largely built on European/global vineyard structures. GrapesNet targets denser, more occluded Indian vineyard conditions, and this project aims to (a) benchmark modern YOLO versions (v11/v12) on it, and (b) develop a new detection architecture from scratch targeting occlusion robustness, validated for generalization across multiple datasets.
- **Deployment target:** The trained model will ultimately run on **live video**, not just static images — so the preprocessing pipeline includes augmentations (e.g. motion blur) chosen specifically to prepare the model for that deployment condition, even though the training data itself is static images.

## What This Pipeline Does

Takes the raw `Dataset/` folder (GrapesNet, as downloaded) and produces a clean, deduplicated, quality-filtered, correctly-split, YOLO-format-ready dataset, with full reports and reproducibility guarantees. The full stage-by-stage specification is in [`PREPROCESSING_PIPELINE.md`](./PREPROCESSING_PIPELINE.md) — that file is the authoritative technical spec and should be read in full before implementing or modifying any pipeline code.

At a high level:

```text
Raw Dataset → Ingest & Validate → Standardize Annotations → Deduplicate
→ Quality Filter → Split (train/val/test) → Resize/Letterbox
→ Normalize → Train-only Augmentation → Ready for YOLO training
```

## Why It's Built This Way

- **Dataset-agnostic by design:** Every stage except annotation-format conversion is written to work on any similarly-structured image/annotation dataset, not just GrapesNet. This matters because the PhD methodology requires testing the final model's generalization on at least one additional dataset (e.g. WGISD) — this pipeline should handle that with minimal changes.
- **Annotation format is auto-detected, not assumed:** At the time this pipeline was specified, the exact annotation format inside the `Dataset/` subfolders was not yet confirmed. Rather than guessing, the pipeline detects VOC XML / COCO JSON / YOLO txt / no-annotation per subfolder and reports what it finds.
- **Leakage-safe:** Because GrapesNet is made of 5 distinct sub-datasets with potentially near-duplicate/burst-captured frames, splitting is group-aware (by subfolder and by duplicate-group) to prevent train/val/test contamination.
- **No silent data loss:** Corrupted, unannotated, low-quality, or duplicate images are never deleted outright — they're quarantined into `data/rejected/` with a logged reason, so nothing is lost without a trace.
